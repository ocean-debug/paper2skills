# Paper2Skill Build Validation / Real Benchmark Revision Plan

## Summary

Paper2Skill has two separate workflows:

1. Build-time validation during skill generation.
2. Independent gold-standard benchmark scoring after a skill has been generated.

`dry_run`, `data_smoke`, and `live_execute` are build-time validation depths.
They help the builder self-check and iteratively improve a child skill. They
are not benchmark scores.

Real benchmark evaluation is independent and gold-based. L2 benchmark scoring
requires complete official example execution and only passes on
`live_execute_success`.

## Build-Time Validation

Build validation is used by `paper2skill build` and generated-skill self-checks.
The default depth is `dry_run`.

- `dry_run`: checks package structure, policy safety, preflight plan, install
  plan, and execution plan without real reproduction.
- `data_smoke`: runs a reviewed core flow on small official or minimal data.
- `live_execute`: runs a reviewed official full example during generation-time
  self-check.

Build validation writes diagnostic reports. It must not write or mutate
benchmark scores.

## Benchmark Levels

- L0: Skill package structure and safety validation. Checks required files,
  adapter lifecycle, notebook execution policy, install policy, local path
  leakage, and safe defaults.
- L1: Static evidence and contract quality. Checks source collection,
  dependency mining, tutorial/workflow, IO/Bio contract, adapter behavior, and
  execution safety plan. Environment repair plan is not an L1 score item.
- L2: Official example live execution. Requires official full example
  `live_execute_success`, real output files, and workflow completeness.
- L3: New or alternative data generalization. Measures whether the generated
  skill can transfer to new or small substitute data; it does not replace L2.
- L4: Agentic command following and safe refusal. Evaluates structured agent
  traces or deterministic mock-agent decisions for correct action selection,
  contract-aware reasoning, required contract references, and forbidden unsafe
  actions.

## L2 Policy

`dry_run`, `data_smoke`, `install_approval_required`, `skipped_by_l2_mode`, and
`blocked_by_policy` do not receive L2 full credit. They are diagnostic or
safety signals.

If a benchmark case lacks a live official example entry, L2 returns structured
failure with `missing_live_official_example_gold`.

BioEnvRebuilder install, repair, and lockfile reports are L2 execution evidence
or diagnostics. They are not part of L1 static scoring.
